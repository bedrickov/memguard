## О проекте

Современные вредоносные импланты (Cobalt Strike, Havoc, Sliver, Brute Ratel) и сложные руткиты давно отказались от сохранения бинарных файлов на диск, перейдя к выполнению в оперативной памяти (In-Memory Evasion). Они используют техники вроде:
1. **Reflective DLL Injection** — загрузка PE-образа напрямую в приватную память без вызова `LoadLibrary`.
2. **Process Hollowing & Doppelgänging** — подмена секций легитимных системных процессов.
3. **EDR Unhooking / Inline Trampolines** — затирание хуков антивирусных систем в `ntdll.dll` и перехват системных вызовов через JMP-трамплины.
4. **RWX Allocations** — выделение страниц с правами `PAGE_EXECUTE_READWRITE` для распаковки зашифрованных шеллкодов.

**MemGuard** — это автономная системная утилита на чистом C++20, созданная для выявления аномалий памяти на нулевом уровне доверия:
- **Zero Third-Party Dependencies**: Никаких тяжелых фреймворков. Только чистый C++20 и нативные Win32 / NTAPI интерфейсы.
- **Детекция нерезервированных страниц**: Анализ приватных исполняемых регионов (`MEM_PRIVATE`), не привязанных ни к одному подписанному модулю на диске (`MEM_IMAGE`).
- **Проверка целостности прологов NTDLL**: Сигнатурный и эвристический анализ первых 16 байт критических системных вызовов (`NtAllocateVirtualMemory`, `NtProtectVirtualMemory`, `NtCreateThreadEx` и др.) на наличие `E9` JMP, `FF 25` Indirect JMP или `48 B8 ... FF E0` патчей.
- **Энтропийный фильтр Шеннона**: Вычисление информационной энтропии в битах на байт (0.0 — 8.0) для мгновенного обнаружения зашифрованных C2-биконов и упакованных шеллкодов.
- **Автоматический дамп**: Возможность выгрузки подозрительных регионов памяти на диск для дальнейшего реверс-инжиниринга в IDA Pro / Ghidra.

## Возможности

- **Мгновенный аудит адресного пространства**: Быстрый обход таблицы дескрипторов страниц через `VirtualQueryEx` с фильтрацией защиты и типов памяти.
- **Поддержка x64 и x86**: Корректная обработка WOW64 процессов и нативных 64-битных адресных пространств (вплоть до верхних границ User-mode памяти).
- **Повышение привилегий**: Автоматический запрос и активация привилегии `SeDebugPrivilege` в токене доступа для работы с системными службами.
- **Эвристический поиск перехватов (API Hooks)**:
  - Относительные переходы `JMP Rel32` (`0xE9`)
  - Косвенные переходы `JMP QWORD [RIP+rel32]` (`0xFF 0x25`)
  - 64-битные регистровые трамплины `MOV RAX, imm64; JMP RAX` (`0x48 0xB8 ... 0xFF 0xE0`)
  - Стек-переходы `PUSH imm32; RET` (`0x68 ... 0xC3`)
  - Программные точки останова `INT3` (`0xCC`)
- **Форматы отчетов**:
  - Высокоинформативный интерактивный CLI с цветовой ANSI-разметкой и карточками инцидентов.
  - Машиночитаемый JSON-экспорт для интеграции в корпоративные SIEM и DevSecOps пайплайны.

## Сборка из исходников

### Требования
- Компилятор с поддержкой C++20:
  - GCC 12+ (MinGW-w64)
  - MSVC (Visual Studio 2022 v17.0+)
  - Clang 15+
- [CMake](https://cmake.org/) версии 3.20 или новее.

### Сборка через PowerShell
```powershell
# Сборка проекта и прогон всех юнит-тестов
.\build.ps1 -Test

# Очистка артефактов
.\build.ps1 -Clean
```

### Сборка через стандартный CMake
```bash
cmake -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
.\build\memguard_tests.exe
```

## Использование CLI

```bash
# Вывести список всех запущенных процессов и их PID
memguard list

# Сканирование процесса по PID
memguard scan --pid 4512

# Сканирование процесса по имени исполняемого файла
memguard scan --name discord.exe

# Сканирование с экспортом результатов в JSON
memguard scan --pid 1337 --json audit_report.json

# Сканирование с дампом подозрительных шеллкодов на диск
memguard scan --name infected_app.exe --dump ./suspicious_dumps

# Расчет информационной энтропии произвольного файла
memguard entropy --file C:\payload.bin

# Анализ энтропии строки
memguard entropy "AAECAwQFBgcICQoLDA0ODxAREhMUFRYXGBkaGxwdHh8="

# Вывод каталога правил обнаружения
memguard rules
```

## Каталог правил

| ID | Важность | Категория | Описание |
| :--- | :--- | :--- | :--- |
| **MG-001** | `CRITICAL` | MemoryInjection | Наличие незамапленного заголовка PE (`MZ` + `PE`) в приватной памяти (`MEM_PRIVATE`) — индикатор Reflective DLL Injection / Process Hollowing |
| **MG-002** | `HIGH` | MemoryProtection | Страница памяти с правами `PAGE_EXECUTE_READWRITE` (RWX) в приватном сегменте — классическая зона распаковки шеллкода или JIT-трамплина |
| **MG-003** | `MEDIUM` | MemoryInjection | Непривязанная исполняемая память (`PAGE_EXECUTE_READ`), не ассоциированная с доверенным PE-модулем на диске |
| **MG-004** | `HIGH` | PayloadAnalysis | Высокая энтропия Шеннона ($H \ge 7.10$ бит/байт) в исполняемой или закрытой памяти (зашифрованный C2-бикон, упаковщик) |
| **MG-005** | `HIGH` | Tampering | Модификация прав секции кода легитимной DLL (`MEM_IMAGE`) на запись — признак инлайн-патчинга или сброса хуков EDR |
| **MG-006** | `CRITICAL` | ApiHooking | Инлайн-перехват (JMP/CALL/RET) системного вызова NTDLL с перенаправлением в нерезервированную память |
